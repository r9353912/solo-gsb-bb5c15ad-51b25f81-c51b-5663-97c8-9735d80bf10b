演算规则说明（点击展开）
  • Domain：无 Domain 属性为 host-only，仅匹配原主机；带 Domain 时匹配该域及所有子域。Domain 不是响应主机本身或其上级域时拒绝入罐；IP 主机不做子域匹配。
  • Path：缺省取响应 URL 最后一个斜杠前的目录（如 /admin/dashboard → /admin）。匹配要求路径相等、或以 cookie-path 开头且边界是 /。
  • Max-Age：正整数为相对有效期秒数；Max-Age=0 或负数会删除同名同域同路径项；非法值忽略（按会话 cookie）。Expires 属性不参与本演算。
  • Secure：仅在 https 请求中发送；明文 http 响应中设置 Secure 会给出提示。
  • SameSite：解析 Strict / Lax / None（大小写不敏感）；未声明或非法值记为默认 Lax；SameSite=None 未带 Secure 时拒绝入罐。
  • Priority：解析 Low / Medium / High（大小写不敏感）；缺省或非法值按 Medium（非法值会给出提示）。容量淘汰时低优先级先出局。
  • Partitioned（CHIPS 独立分区）：无值标志属性。仅当同时带 Secure、且写入时提供的顶层页面 URL 为有效 http(s) 地址时才入罐，否则拒绝；分区键 = 该 URL 的 scheme + 可注册域（IP、localhost 用完整主机）。分区键是存储身份的一部分：普通项与不同分区的同名同域同路径项并存，覆盖与 Max-Age<=0 删除只影响对应分区。发送时按顶层页面 URL 计算请求分区键，仅键相同的分区项发送，键不同的分区项在排除明细说明原因；普通（未分区）项不受影响。分区项同样计入域级与全局容量。
  • 容量压力：可分别为每个可注册域（eTLD+1；IP / localhost 按完整主机）与全局设置条目数上限。入罐通过全部校验后，先执行域级淘汰、再执行全局淘汰；仅在范围内条数超限时动作：先清理过期项，仍超限再按 Priority 低→高、最近访问时间早→晚、创建序号小→大 依次淘汰，直到回到上限。修改容量设置会立即执行一次。
  • 最近访问（LRA）：创建 / 覆盖更新时写入访问时间；条目发送成功即刷新。同级 Priority 中越久未访问越先被淘汰。
  • 站点（site）：scheme + 可注册域（eTLD+1，由公共后缀列表 PSL 判定，如 https://example.com）；IP 与 localhost 按完整主机比较。请求站 = 顶层站即「同站」。
  • 发送限制：Strict 仅同站发送；显式 Lax 仅同站或跨站顶层导航的安全方法（GET/HEAD/OPTIONS/TRACE）发送；默认 Lax 额外允许创建不超过 120 秒的跨站顶层 POST；None 跨站照常发送（已强制 Secure）。
  • 屏蔽第三方 Cookie（可选，默认关闭）：界面开关与 /api/store、/api/send 的 blockThirdParty 参数一一对应。开启后必须提供有效顶层页面 URL，按 scheme + 可注册域判定它与响应/请求 URL 是否跨站：跨站响应拒绝写入和删除普通 Cookie（不改动罐、不触发容量淘汰），Partitioned 分区项仍按既有 Secure 与分区键规则处理；跨站请求排除普通 Cookie（被排除条目不刷新最近访问时间），分区键匹配的 Partitioned 项仍可发送。拒绝/排除结果逐项说明策略原因。
  • document.cookie 脚本演算（右栏「📜 document.cookie 演算」面板，对应 /api/script/read、/api/script/write）：模拟页面 JS 视角。读取按既有 过期 → 分区（Partitioned 分区键）→ 第三方屏蔽 → Domain → Path → Secure 顺序筛选，最后再排除 HttpOnly（document.cookie 对脚本不可见）；不应用 SameSite，且不刷新最近访问时间（纯只读、罐内容不变）；可读项沿用请求头排序（Path 长度降序、创建序号升序），逐项给出可读/不可读原因，并以 ; 拼成 document.cookie 字符串。写入复用既有解析、分区身份与容量逻辑，但拒绝带 HttpOnly 的赋值，也拒绝覆盖或以 Max-Age<=0 删除同身份（name、domain、path、分区键相同）且未过期的 HttpOnly 项；已过期的 HttpOnly 项不在保护之列。脚本专属拒绝都在改动罐之前返回，罐内容、时间戳与容量均不变。网络接口 /api/store、/api/send 行为不变，仍可写入、更新、删除并在请求头中发送 HttpOnly 项。
  • 演算时钟（右栏「⏱ 演算时钟」面板，对应 GET /api/clock、POST /api/clock/advance）：服务启动时固定当前真实时间为演算时钟起点，之后不随真实时间流动，只能按正整数秒推进；非法输入（0、负数、非整数、非数字）被拒绝且时钟与罐均不变。网络写入/发送、document.cookie 读写、罐快照与容量淘汰统一使用该时钟——Max-Age 过期、默认 Lax 的 120 秒跨站顶层 POST 宽限、过期清理都可逐步复现。推进本身不删除条目：过期项留在罐中标灰展示，下次匹配或容量淘汰时再按既有规则处理；重置罐时时钟同步回到启动时刻。
  • 场景快照（「🫙 当前 Cookie 罐」面板，对应 GET /api/snapshot、POST /api/snapshot/import）：快照下载导出带格式标识与版本号的 JSON：原始 Cookie 条目（含分区键、创建序号、创建/更新/最近访问时间等全部字段，非展示视图）、容量规则（全局与每可注册域上限）、演算时钟起点与当前值及下一创建序号。快照导入先做完整校验——结构与字段类型、时间范围（时钟当前值不早于起点且为整秒推进；条目时间均落在起点与当前值之间）、条目身份唯一性（name、domain、path、分区键不重复；创建序号不重复）、序号一致性（创建序号 ≥1 且严格小于下一序号），以及 SameSite=None 必带 Secure、Partitioned 必带分区键等枚举约束——任一不满足即拒绝；全部通过后才一次性替换罐、容量规则与时钟，失败时旧罐、容量和时钟均不变。恢复是精确状态替换、不执行容量淘汰：过期项原样保留，恢复后的发送排序（Path 长度 / 创建序号）、默认 Lax 的 120 秒跨站顶层 POST 宽限（按首次创建时间）与容量淘汰（Priority / 最近访问 / 创建序号）与导出前的连续操作完全一致；新写入条目从快照的下一序号继续编号。
  • 排序：发送时按 Path 长度降序，Path 等长时按首次创建顺序升序，再以 ; 拼接成 Cookie 头。
  • 重定向链演算（左栏「重定向链演算」面板，对应 POST /api/redirect-chain）：输入起始 URL、方法、固定顶层页面 URL、顶层导航与第三方屏蔽开关，以及最多 8 个响应步骤（每步：状态码、Location、Set-Cookie 字符串列表）。提交时先对整条链与每一跳的 http(s) 目标做完整预校验（起始/顶层 URL、状态码与 Location 组合、相对 Location 解析结果仍须 http(s)、Set-Cookie 列表类型），任一失败返回 400 且罐保持不变。校验通过后逐跳执行：每跳先按现有规则生成 Cookie 请求头（展示发送 / 排除项与原因），再按响应 URL 顺序逐条写入该跳 Set-Cookie（展示每条的入罐 / 更新 / 删除 / 拒绝结果与容量淘汰）。末跳必须为 200 且无 Location；跳转状态码仅 301/302/303/307/308；相对 Location 基于当前 URL 解析。方法改写：303 后续一律 GET（HEAD 保留），301/302 仅把 POST 改 GET，307/308 保留方法；所有跳沿用同一顶层页面 URL / 顶层导航 / 第三方屏蔽设置。结果展示每跳 URL、方法、Cookie 头、各 Set-Cookie 写入结果与最终罐。
